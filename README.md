# 校园快递驿站包裹管理系统 (Campus Parcel Station Management System)

> **项目状态**：🚧 需求调研与初步设计阶段 (Requirement Analysis & Initial Design)
> **版本**：v0.1-alpha

## 📖 项目简介
本项目旨在为高校快递驿站提供一套轻量级、高效率的**微型仓储管理系统（Mini-WMS）**。系统聚焦于包裹“到件之后”的驿站内部流转环节，通过数字化手段解决取件排队、错拿丢件、滞留件堆积及代取不便等真实痛点。

> **系统边界说明**：本系统仅负责包裹到达驿站后的入库、上架、通知、出库及异常处理环节，不涉及上游快递公司的揽收与干线运输，不涉及支付交易行为。

## 🎯 业务背景与痛点
通过对校园快递驿站的初步观察与干系人访谈，我们识别出以下核心痛点：
1. **高峰期拥堵**：取件排队时间长，人工核对效率低。
2. **找件困难**：包裹乱堆放，缺乏库位管理，员工找件耗时。
3. **代取安全**：简单截图取件码容易泄露，缺乏可信的代取授权机制。
4. **异常件难追溯**：错件、漏件、滞留件缺乏状态跟踪与申诉流转机制。

## 👥 目标用户角色 (Role Matrix)
系统初步规划包含以下用户角色（后续可能随调研细化）：
- **学生/收件人**：接收取件通知，出示取件码，发起代取授权或异常申诉。
- **驿站员工**：包裹入库登记、上架库位分配、扫码核销出库。
- **驿站站长**：员工排班管理、异常申诉审批、滞留件退回处理、数据报表查看。
- **代取人**：通过被授权的动态凭证代为领取包裹。

## ✨ 核心业务模块 (初步规划)
基于当前分析，系统核心业务闭环如下：
- **入库管理**：单件扫码/批量导入录入、库位分配算法（如：A区-03架-2层）。
- **出库核销**：取件码/扫码强校验出库、防重复出库（幂等性设计）。
- **代取授权**：线上发起代取请求，生成具有时效性的动态授权码。
- **异常与滞留管理**：超时滞留预警、一键退回登记、错件/丢件申诉工单流转。
- **看板与报表**：站长端实时看板（在库量、今日入库/出库量、滞留率）。

## 🔄 核心领域模型 (Domain Model - 预研)
系统围绕**包裹生命周期**展开，初步状态机流转如下（技术风险点：需保证并发核销时的状态机一致性）：
`在途(In Transit) -> 到件(Arrived) -> 已上架(Stored) -> 已取件(Picked Up) / 滞留(Overdue) / 退回(Returned)`
